Dokumentasi Project: Part of Me (Portfolio)
============================================
Catatan ini melengkapi style_note_tailwind.txt (yang fokus ke detail konversi

1. TECH STACK
==============

- Next.js 16.2.9 (App Router, Turbopack) — framework utama, routing lewat
  folder src/app, route handler API lewat app/api/*/route.ts.
- React 19.2.4 + React DOM 19.2.4
- TypeScript ^5 — semua komponen pakai .tsx, dicek lewat `npx tsc --noEmit`.
- Tailwind CSS v4 (^4) + @tailwindcss/postcss — satu-satunya sistem styling
  di project ini (lihat src/app/globals.css). Tidak ada Bootstrap CSS/JS.
- ESLint ^9 + eslint-config-next 16.2.9
- framer-motion ^12.42.2 — dipakai untuk animasi scroll-reveal di Hero
  (lihat poin Hero di bawah).
- lucide-react ^1.22.0 — icon set. PENTING: versi ini TIDAK punya icon brand
  seperti Github/Linkedin (beda dari versi lucide-react yang umum dipakai
  tutorial). Icon yang tersedia & dipakai di project: Mail, Phone, MapPin,
  Code2, Rocket, Users, Layout, Server, Database, ShoppingCart,
  LayoutDashboard, ListChecks, ExternalLink, ArrowDown, Computer.
  Kalau butuh icon baru, cek dulu apakah namanya benar-benar ada di
  node_modules/lucide-react/dist/lucide-react.d.ts sebelum dipakai.
- resend ^6.17.1 — SDK untuk kirim email dari server (dipakai di
  src/app/api/contact/route.ts untuk form Contact).
- next-auth ^5.0.0-beta.31 (Auth.js v5) — autentikasi admin. Install pakai
  `npm install next-auth@beta`, BUKAN tag `latest` — dist-tag `latest` di
  npm untuk package ini masih v4 (bergaya Pages Router, tidak cocok untuk
  App Router). Dipakai untuk login /admin.
- prisma ^7.8.0 + @prisma/client ^7.8.0 — ORM untuk database yang
  menyimpan konten Projects/Skills/About yang bisa diedit lewat /admin.
- @prisma/adapter-neon + @neondatabase/serverless — driver adapter untuk
  Postgres di Neon (WAJIB di Prisma 7, lihat gotcha di bawah). UPDATE:
  sebelumnya project ini pakai SQLite lokal + @prisma/adapter-better-
  sqlite3, SEKARANG sudah pindah ke Postgres (hosted di Neon,
  neon.tech) — package sqlite-nya sudah di-uninstall, tidak dipakai lagi.
- bcryptjs ^3.0.3 — hash password admin (pure JS, bukan native `bcrypt`,
  supaya tidak ada masalah kompilasi native module di Turbopack).
- tsx ^4.23.0 (devDependency) — buat menjalankan prisma/seed.ts (TypeScript
  langsung, tanpa build step terpisah).
- dotenv ^17.4.2 (devDependency) — dipakai manual di prisma.config.ts dan
  prisma/seed.ts untuk load .env / .env.local (lihat poin ENV di bawah).

Gotcha lain yang perlu diingat:
- Tailwind v4 di versi ini TIDAK otomatis membuatkan utility class dari
  custom theme token `--ease-*` (mis. `--ease-ios` tidak menghasilkan class
  `ease-ios`). Kalau pakai easing custom di `@apply`, harus pakai arbitrary
  value langsung: `ease-[cubic-bezier(...)]`.
- Gradient utility di Tailwind v4 namanya `bg-linear-to-*` / `bg-radial`
  (BUKAN `bg-gradient-to-*` seperti Tailwind v3).
- Kalau menggabungkan utility `animate-*` dengan arbitrary property
  `[animation-delay:...]` dalam satu `@apply`, Tailwind bisa salah compile
  jadi animation-name kosong. Solusinya: masukkan delay langsung ke dalam
  shorthand `--animate-*` (mis. `nama-animasi 18s ease-in-out 5s infinite`).
- `FormEvent`/`FormEventHandler` dari @types/react versi ini sudah
  @deprecated ("doesn't actually exist"). Untuk form submit pakai
  `SubmitEvent<HTMLFormElement>` sebagai gantinya.
- Next.js 16 mengganti nama "Middleware" jadi "Proxy": file konvensinya
  sekarang `proxy.ts` (bukan `middleware.ts`) di root project, dengan
  fungsi bernama `proxy` (bukan `middleware`). `middleware.ts` lama masih
  jalan tapi deprecated. Proxy di versi ini SELALU jalan di Node.js runtime
  (bukan Edge) — opsi `runtime` tidak bisa di-set di proxy.ts.
- Prisma 7 WAJIB pakai driver adapter untuk semua datasource (SQLite
  MAUPUN Postgres) — `new PrismaClient()` polos yang cuma mengandalkan
  `datasource url` di schema.prisma sudah TIDAK JALAN lagi (akan error
  runtime). Untuk Postgres/Neon: `new PrismaClient({ adapter: new
  PrismaNeon({ connectionString }) })` dari package `@prisma/adapter-neon`
  (butuh `@neondatabase/serverless` juga sebagai peer dependency-nya).
- Prisma 7 juga ganti default generator jadi `prisma-client` (bukan
  `prisma-client-js`), output-nya ke folder sendiri (di project ini:
  src/generated/prisma, sudah di-gitignore otomatis oleh `prisma init`),
  BUKAN ke node_modules/@prisma/client seperti versi lama. Import client-nya
  dari path itu langsung (lihat src/lib/prisma.ts), bukan dari
  `@prisma/client`.
- Prisma 7 juga pindah config (schema path, migrations path, seed command,
  datasource url) ke file `prisma.config.ts` di root, BUKAN lagi lewat key
  `"prisma"` di package.json. Command seed dikonfigurasi lewat
  `migrations.seed` di prisma.config.ts.
- PENTING (baru ketahuan pas migrasi ke Neon): di Prisma 7, field `url`
  dan `directUrl` di blok `datasource db { ... }` pada schema.prisma
  SUDAH TIDAK BOLEH DITULIS SAMA SEKALI — kalau ditulis, `prisma migrate`
  akan error validation ("no longer supported in schema files"). Connection
  string SEKARANG WAJIB ditaruh di `prisma.config.ts` lewat key
  `datasource.url`, bukan di schema.prisma. schema.prisma sekarang cuma
  berisi `provider = "postgresql"` saja untuk blok datasource-nya.
- `prisma.config.ts` TIDAK otomatis baca `.env.local` — dia cuma baca
  `.env` lewat `import "dotenv/config"`. Karena project ini sudah biasa
  pakai `.env.local` (konvensi Next.js) untuk secret, DATABASE_URL &
  DIRECT_URL taruh di `.env` biasa (dibaca Prisma CLI & tetap kebaca
  Next.js juga), sedangkan AUTH_SECRET/ADMIN_EMAIL/ADMIN_PASSWORD tetap di
  `.env.local`. Supaya prisma/seed.ts bisa baca ADMIN_EMAIL/ADMIN_PASSWORD
  dari `.env.local`, di dalam seed.ts manual dipanggil `config()` lalu
  `config({ path: '.env.local', override: true })` dari package `dotenv`.
- Neon (dan kebanyakan Postgres serverless) kasih DUA connection string:
  **pooled** (hostname ada akhiran `-pooler`, lewat PgBouncer, dipakai buat
  query aplikasi sehari-hari karena cocok untuk banyak koneksi pendek ala
  serverless) dan **direct/unpooled** (hostname tanpa `-pooler`, dipakai
  KHUSUS untuk `prisma migrate` karena operasi DDL/locking migration bisa
  bermasalah lewat connection pooler). Pembagiannya di project ini:
  `prisma.config.ts` (dipakai CLI/migrate) → `DIRECT_URL`. `src/lib/
  prisma.ts` & `prisma/seed.ts` (dipakai aplikasi jalan/seed data) →
  `DATABASE_URL` (pooled).
- BUG PENTING yang ditemukan & diperbaiki: kalau `proxy.ts` (dulu
  middleware) di-set untuk melindungi path `/admin/:path*`, dan ada Server
  Action di halaman itu yang memanggil `redirect(...)` setelah mutasi
  (mis. createProject), maka SESSION COOKIE bisa hilang dan user ke-logout
  paksa! Ini karena Server Action nge-POST balik ke URL halaman itu sendiri
  (mis. POST /admin/projects/new), yang otomatis ke-match juga oleh proxy
  matcher yang sama, dan interaksi keduanya menghapus cookie. Next.js
  sendiri memperingatkan hal ini di dokumentasinya ("a Proxy matcher that
  excludes a path will also skip Server Function calls on that path...
  always verify authentication inside each Server Function"). Perbaikan:
  di proxy.ts, exclude request yang punya header `next-action`:
  `matcher: [{ source: '/admin/:path*', missing: [{ type: 'header', key:
  'next-action' }] }]`. DAN sebagai lapis kedua, setiap Server Action di
  src/app/admin/**/actions.ts sekarang manggil `await requireAdmin()`
  (dari src/lib/require-admin.ts) di baris pertama, tidak cuma
  mengandalkan proxy.
- BUG lain (production only, `next start`): Auth.js menolak request dengan
  error "UntrustedHost" kalau host (mis. localhost) tidak ditandai
  trusted. Perbaikan: `trustHost: true` di auth.config.ts.


2. DEPENDENCIES / NPM INSTALL YANG DIJALANKAN
================================================

Sudah terpasang duluan sebelum sesi ini (ada di package.json awal):
- next, react, react-dom, typescript, tailwindcss, @tailwindcss/postcss,
  eslint, eslint-config-next, @types/node, @types/react, @types/react-dom
- framer-motion (sudah ada di package.json, tinggal dipakai untuk animasi
  Hero — tidak perlu install ulang)
- lucide-react (sudah ada, dipakai untuk semua icon di project)

Yang di-install baru selama sesi Contact form:
- `npm install resend` — untuk fitur "Contact form kirim email otomatis"
  (sebelumnya cuma pakai mailto: link).

Yang di-install baru selama sesi Admin CMS (login + /admin):
- `npm install next-auth@beta bcryptjs prisma @prisma/client
  @prisma/adapter-better-sqlite3 better-sqlite3` — auth + database layer
  (database-nya waktu itu masih SQLite lokal).
- `npm install -D tsx dotenv` — buat menjalankan prisma/seed.ts dan load
  env var manual di situ.

Yang berubah selama sesi migrasi ke Neon (Postgres):
- `npm install @prisma/adapter-neon @neondatabase/serverless` — driver
  adapter Postgres untuk Neon, menggantikan driver SQLite.
- `npm uninstall @prisma/adapter-better-sqlite3 better-sqlite3` — sudah
  tidak dipakai sama sekali, dihapus supaya tidak jadi dependency mubazir.

Kalau clone fresh, urutan setup-nya:
1. `npm install` (baca semua dependency di package.json).
2. Isi `.env` dan `.env.local` (lihat poin 4) — perlu bikin/punya akses ke
   database Postgres (di project ini pakai Neon, neon.tech) dan ambil
   connection string pooled + direct-nya.
3. `npx prisma migrate dev` (bikin tabel-tabel di database Postgres itu).
4. `npx prisma db seed` (isi database dengan admin user + konten awal).
5. `npm run dev`.

prisma/schema.prisma
  - Definisi semua tabel: AdminUser (email + password hash), Project,
    SkillGroup + SkillSubgroup (relasi 1-ke-banyak, `onDelete: Cascade`),
    AboutContent (1 baris singleton, id="about"), AboutHighlight.

    (padahal Postgres sebenarnya dukung `String[]` asli) supaya tidak
    perlu ubah semua kode JSON.parse/stringify yang sudah ada. Bisa
    disederhanakan nanti kalau mau (lihat poin 5 "belum dikerjakan").
  - Blok `datasource db` CUMA berisi `provider = "postgresql"` — TIDAK
    ada `url`/`directUrl` di sini (lihat gotcha Prisma 7 di poin 1,
    connection string-nya ada di prisma.config.ts, bukan di sini).

prisma.config.ts
  - Config Prisma 7 (menggantikan key "prisma" di package.json versi
    lama): lokasi schema, lokasi migrations, command seed
    (`tsx prisma/seed.ts`), dan `datasource.url` dari
    `process.env.DIRECT_URL` (di-load lewat `import "dotenv/config"` di
    baris atas file ini) — SENGAJA pakai DIRECT_URL (bukan DATABASE_URL)

    direct di poin 1).

prisma/seed.ts
  - Script sekali-jalan (`npx prisma db seed`) yang mengisi database:
    1 AdminUser (password di-hash bcryptjs dari ADMIN_EMAIL/ADMIN_PASSWORD
    di .env.local), 3 Project, 3 SkillGroup + 4 SkillSubgroup,
    1 AboutContent, 3 AboutHighlight — semua datanya adalah COPY PERSIS
    dari isi hardcoded yang tadinya ada di AboutSection/SkillsSection/
    ProjectsSection, supaya migrasi ke database tidak mengubah tampilan.
  - Pakai `prisma.<model>.upsert()` untuk AdminUser & AboutContent supaya
    aman dijalankan berkali-kali (tidak duplikat), tapi `createMany()`
    untuk Project/SkillGroup/dll (kalau dijalankan ulang akan duplikat —
    ini script seed sekali pakai, bukan migration yang idempotent penuh).
  - Adapter-nya pakai `PrismaNeon` + `DATABASE_URL` (pooled) — beda
    dengan prisma.config.ts yang pakai DIRECT_URL, karena ini query data
    biasa (insert/upsert), bukan operasi migration.

src/lib/prisma.ts

  - UPDATE: sebelumnya pakai `PrismaBetterSqlite3` (SQLite lokal), sudah

src/lib/require-admin.ts

auth.config.ts (di root project, BUKAN di src/)
  - Config Auth.js yang "ringan": `pages.signIn: '/login'`,
    `trustHost: true`, callback `authorized()` yang menentukan apakah user
    boleh akses `/admin/*` (return true/false berdasarkan `auth?.user`).
    SENGAJA tidak import Prisma/bcrypt di sini (dipakai bareng oleh
    proxy.ts yang seharusnya tetap ringan, walau di Next 16 proxy sudah
    jalan di Node.js runtime jadi ini lebih soal konvensi/kebersihan
    daripada keharusan teknis Edge runtime).

auth.ts (di root project)
  - Config Auth.js LENGKAP: `NextAuth({ ...authConfig, session: {strategy:
    'jwt'}, providers: [Credentials({...})] })`. Provider Credentials
    cek email ke tabel AdminUser lewat Prisma, lalu `bcrypt.compare()`
    password. Export `{ handlers, auth, signIn, signOut }` dipakai di
    tempat lain (route handler, Server Action login/logout, layout admin).

proxy.ts (di root project — INI BUKAN middleware.ts, lihat gotcha di
poin 1 soal penamaan baru Next.js 16)
  - Proteksi route `/admin/:path*`: kalau belum login, redirect ke
    /login (lewat callback `authorized` di auth.config.ts).
  - Matcher sengaja exclude request yang punya header `next-action`
    (skip Server Action POST) — lihat gotcha BUG PENTING di poin 1.

src/app/api/auth/[...nextauth]/route.ts
  - Route handler wajib buat Auth.js: cuma re-export `{ GET, POST }` dari
    `handlers` di auth.ts. Menangani endpoint seperti
    /api/auth/callback/credentials, /api/auth/session, dll secara
    otomatis (tidak perlu disentuh manual).

src/app/login/page.tsx + LoginForm.tsx + actions.ts

src/app/admin/layout.tsx
  - Server component: `await auth()`, kalau belum login `redirect('/login')`

4. ENVIRONMENT VARIABLES
===========================

Ada DUA file env sekarang (keduanya sudah otomatis ke-gitignore lewat pola
`.env*` di .gitignore — jangan pernah commit salah satunya):

.env (dibaca Prisma CLI via prisma.config.ts, JUGA kebaca Next.js sebagai
fallback paling rendah prioritasnya):

  DATABASE_URL="postgresql://<user>:<password>@<host>-pooler.<region>.aws.neon.tech/<db>?sslmode=require&channel_binding=require"
  DIRECT_URL="postgresql://<user>:<password>@<host>.<region>.aws.neon.tech/<db>?sslmode=require&channel_binding=require"

  (UPDATE: sebelumnya cuma ada DATABASE_URL="file:./dev.db" waktu masih
  SQLite lokal. Sekarang dua-duanya string Postgres dari Neon — bedanya
  cuma hostname DATABASE_URL ada akhiran "-pooler", DIRECT_URL tidak.
  Lihat gotcha "pooled vs direct" di poin 1 kenapa harus dua-duanya.)

.env.local (dibaca Next.js runtime seperti biasa; TIDAK dibaca Prisma CLI
secara langsung, tapi prisma/seed.ts sengaja load ini juga secara manual):

  RESEND_API_KEY=<api key dari resend.com>
  AUTH_SECRET=<random string, generate pakai `openssl rand -base64 32`>
  ADMIN_EMAIL=admin@partofme.dev
  ADMIN_PASSWORD=ChangeMe123!

Catatan tiap key:
- DATABASE_URL / DIRECT_URL — connection string ke database Postgres di
  Neon (neon.tech). Ambil dari dashboard project Neon → widget
  "Connection Details". Tanpa ini, seluruh aplikasi tidak bisa jalan sama
  sekali (bukan cuma satu fitur) karena semua Server Component homepage
  (About/Skills/Projects) dan seluruh /admin fetch dari sini.
- RESEND_API_KEY — tanpa ini (atau masih placeholder), form Contact tetap
  bisa diklik tapi gagal kirim (endpoint balas 502, UI nunjukin pesan
  error). Akun gratis Resend tanpa verifikasi domain cuma bisa kirim dari
  `onboarding@resend.dev` dan cuma bisa kirim KE alamat email yang dipakai
  daftar akun Resend itu sendiri.
- AUTH_SECRET — wajib ada untuk Auth.js (dipakai buat sign/encrypt JWT
  session). Kalau kosong, Auth.js akan error saat production build/run.
- ADMIN_EMAIL / ADMIN_PASSWORD — HANYA dipakai sekali saat
  `npx prisma db seed` untuk membuat baris AdminUser (password di-hash
  bcryptjs sebelum disimpan). Setelah di-seed, ganti env var ini TIDAK
  otomatis mengubah password admin yang sudah ada di database — kalau mau
  ganti password admin, harus lewat query database langsung atau hapus &
  seed ulang baris AdminUser-nya.
  PENTING: ganti ADMIN_PASSWORD dari default "ChangeMe123!" sebelum project
  ini dipakai serius / di-deploy.

dites `npm run build` + `npm run start` lokal, hasilnya sukses). Kalau
mau deploy, tinggal push ke git + connect repo-nya di Vercel dashboard,
lalu isi env var di atas sebelum build pertama jalan.


7. LOGIN ADMIN & CARA JALANIN
================================
1. Pastikan sudah `npx prisma migrate dev` + `npx prisma db seed` (lihat
   poin 2).
2. `npm run dev`, buka http://localhost:3000/login (atau klik tombol
   "Admin Dashboard" di Navbar/Hero).
3. Login pakai ADMIN_EMAIL/ADMIN_PASSWORD dari .env.local.
4. Setelah login masuk ke /admin — sidebar kiri ada menu Overview,
   Projects, Skills, About. Semua perubahan lewat form di sini langsung
   ke-refleksi di homepage publik (berkat `revalidatePath('/')` di setiap
   Server Action mutasi) — bahkan di production build (`npm run build`
   lalu `npm run start`) di mana halaman `/` di-prerender statis saat
   build; tanpa revalidatePath, perubahan admin TIDAK akan pernah muncul
   di halaman publik sampai rebuild ulang.
5. Logout lewat tombol "Log out" di bagian bawah sidebar.


8. POPUP SUCCESS/FAILED ALA SWEETALERT DI /admin
===================================================
Semua tombol Save (Project/SkillGroup/Highlight/Bio) dan Delete
(Project/SkillGroup/Highlight) sekarang nampilin popup modal — bukan
langsung pindah halaman diam-diam kayak sebelumnya. Popup-nya reuse
class `.modal-overlay`/`.modal-box` yang dari awal project sudah
disiapkan di globals.css tapi belum pernah kepakai (dipakai buat
`AlertModal.tsx`, komponen baru di src/app/admin/AlertModal.tsx).

Kenapa TIDAK pakai library `sweetalert2`: styling default SweetAlert2
tidak nyambung sama desain Tailwind project ini, dan project sudah punya
class modal siap pakai sendiri — jadi bikin komponen sendiri lebih
ringkas (tidak nambah dependency) dan otomatis konsisten sama tema warna
di globals.css (pakai `.bg-success-subtle`/`.bg-danger-subtle` yang juga
sudah ada dari awal).

Perubahan arsitektur penting (KENAPA formnya jadi 'use client'):
- SEBELUMNYA: `createProject`/`updateProject`/dst langsung manggil
  `redirect('/admin/projects')` di akhir Server Action — begitu sukses,
  browser langsung pindah halaman, tidak ada "jeda" buat nampilin popup.
- SEKARANG: action-nya TIDAK redirect lagi, tapi RETURN
  `{ success: boolean, message: string }` (tipe `ActionResult` di
  src/app/admin/actionResult.ts). Form-nya (ProjectForm/SkillGroupForm/
  HighlightForm/BioForm) jadi client component yang pakai
  `useActionState` (React 19) buat nangkep hasil itu, lalu manggil
  `showAlert()`. Baru SETELAH user klik "OK" di popup (kalau sukses),
  baru `router.push()` ke halaman list — jadi pindah halamannya terjadi
  setelah user lihat & tutup popup, bukan langsung.

BUG yang ketemu pas testing & cara perbaikinya (PENTING, jangan diulang):
Percobaan PERTAMA, tiap form/DeleteButton nyimpen state popup-nya SENDIRI
(`useState` lokal) dan render `<AlertModal>`-nya sendiri-sendiri. Ternyata
untuk tombol DELETE ini gagal total — popup-nya TIDAK PERNAH muncul.
Sebabnya: begitu `deleteProject` (atau sejenisnya) selesai, action itu
manggil `revalidatePath('/admin/projects')`, yang bikin Next.js
me-refresh Server Component list-nya — baris (row) untuk item yang baru
dihapus itu ikut hilang dari DOM, dan `DeleteButton` yang ada DI DALAM
baris itu ikut ke-unmount BERSAMAAN dengan (atau bahkan SEBELUM)
`setAlert(...)` sempat jalan. Jadi state popup-nya sempat di-set, tapi
komponennya sendiri sudah tidak ada lagi buat menampilkannya.

Perbaikannya: state popup-nya DIPINDAH ke satu tempat yang TIDAK IKUT
hilang waktu list di-refresh — yaitu `AlertProvider.tsx` (React Context),
yang dipasang SEKALI di `src/app/admin/layout.tsx` (level layout, bukan
level halaman/baris), sehingga dia tetap hidup walau konten di bawahnya
(halaman list, baris-barisnya) berubah/hilang. `DeleteButton` dan
`useAdminForm` sekarang cuma manggil `showAlert()` dari `useAlert()`
(hook context-nya), TIDAK nyimpen/render `<AlertModal>` sendiri lagi.
Pelajarannya: kalau ada popup/notifikasi yang dipicu oleh aksi yang BISA
bikin komponen pemicunya sendiri hilang dari DOM (delete, navigasi,
dll), state-nya HARUS hidup di komponen leluhur yang tidak ikut hilang,
bukan di komponen yang memicu aksi itu sendiri.

File-file yang ikut berubah untuk fitur ini (selain yang sudah disebut
di poin 3): actions.ts di projects/skills/about (return ActionResult,
bukan redirect), ProjectForm.tsx, SkillGroupForm.tsx, HighlightForm.tsx,
BioForm.tsx (baru, dipisah dari admin/about/page.tsx) — semua jadi
'use client' + pakai useAdminForm (TANPA render AlertModal sendiri),
DeleteButton.tsx (try/catch + showAlert), AlertProvider.tsx (baru),
admin/layout.tsx (dibungkus AlertProvider), dan tiap halaman new/[id]/
list yang manggil form-form itu (tambah prop `redirectTo` /
`successMessage`).

Kalau mau nambah CRUD baru dengan popup yang sama (ikuti pola di atas):
1. Action-nya return `Promise<ActionResult>` dengan signature
   `(prevState: ActionResult | null, formData: FormData) => ...`
   (kalau ada param tambahan kayak `id`, taruh SEBELUM `prevState`, lalu
   `.bind(null, id)` pas dipakai — persis kayak updateProject).
2. Form component-nya `'use client'`, panggil
   `useAdminForm(action, redirectTo)` dari src/app/admin/useAdminForm.ts
   — TIDAK perlu render `<AlertModal>` sendiri, sudah otomatis lewat
   AlertProvider yang dipasang di admin/layout.tsx.
3. Untuk delete, cukup pakai `<DeleteButton action={...} confirmMessage=
   {...} successMessage={...} />` yang sudah ada, tidak perlu bikin baru.
