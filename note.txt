Dokumentasi Project: Part of Me (Portfolio)
============================================
Versi ringkas — fokus ke fakta yang dipakai buat kerja, bukan narasi/riwayat
chat. Detail konversi Bootstrap->Tailwind ada di style_note_tailwind.txt.


1. TECH STACK
==============
- Next.js 16.2.9 (App Router, Turbopack), React 19, TypeScript ^5
- Tailwind CSS v4 — satu-satunya sistem styling (src/app/globals.css)
- framer-motion — animasi scroll-jacking Hero
- lucide-react — icon set. Versi ini TIDAK ada icon brand (Github/Linkedin
  dst). Cek node_modules/lucide-react/dist/lucide-react.d.ts sebelum pakai
  icon baru.
- resend — kirim email dari Contact form (api/contact/route.ts)
- next-auth@beta (Auth.js v5) — login admin. Install pakai tag `@beta`,
  BUKAN `latest` (masih v4, tidak cocok App Router).
- prisma 7 + @prisma/adapter-neon + @neondatabase/serverless — ORM +
  Postgres serverless (Neon, neon.tech)
- bcryptjs — hash password admin
- @vercel/blob — upload/hapus screenshot project (src/lib/blob.ts)
- @google/genai + react-markdown — chatbot AI (Gemini) + render balasannya


2. SETUP / CARA JALANIN
=========================
1. `npm install` (otomatis trigger `postinstall`: `prisma generate`)
2. Isi `.env` dan `.env.local` (lihat poin 3)
3. `npx prisma migrate dev`
4. `npx prisma db seed`
5. `npm run dev` → buka http://localhost:3000
6. Login admin: http://localhost:3000/login, pakai ADMIN_EMAIL/
   ADMIN_PASSWORD dari `.env.local`. Sidebar /admin: Overview, Projects,
   Skills, About. `revalidatePath('/')` dipanggil tiap Server Action
   mutasi jadi perubahan langsung tampil di homepage publik.


3. ENVIRONMENT VARIABLES
===========================
Dua file, keduanya gitignored lewat `.env*` — JANGAN pernah di-commit.

.env — dibaca Prisma CLI (via prisma.config.ts, yang TIDAK baca .env.local):
  DATABASE_URL   = connection string Neon, pooled (hostname ada -pooler)
  DIRECT_URL     = connection string Neon, unpooled (dipakai `prisma migrate`)

.env.local — dibaca Next.js runtime:
  RESEND_API_KEY       = resend.com — tanpa ini, Contact form gagal kirim
                         (502) tapi UI tetap jalan
  AUTH_SECRET          = random string (`openssl rand -base64 32`)
  ADMIN_EMAIL          = dipakai SEKALI pas `prisma db seed`. Ganti env ini
                         TIDAK mengubah password yang sudah ke-seed — harus
                         lewat query DB langsung atau seed ulang.
  ADMIN_PASSWORD       = idem. GANTI dari default sebelum dipakai serius.
  BLOB_READ_WRITE_TOKEN = token dari Blob store di dashboard Vercel. Store-nya
                         WAJIB mode **Public** (bukan default Private), dan
                         TIDAK BISA diganti mode-nya setelah dibuat — kalau
                         salah, hapus & bikin store baru (token ikut ganti).
  GEMINI_API_KEY       = aistudio.google.com/apikey (gratis). Tanpa ini,
                         chatbot gagal sopan (pesan error), fitur lain normal.

==================
- Admin bisa edit lewat /admin: Projects, Skills, About (bio + highlights)
- BELUM bisa diedit dari admin: Hero, Contact, Footer, Navbar (teks masih
  di translations.ts / hardcoded)
- Upload gambar cuma ada untuk Project screenshot. Foto profil About & foto
  Hero masih file statis di /public/images (belum ada field DB-nya)
- Toggle bahasa EN/ID SEKARANG translate SEMUA teks deskriptif, termasuk
  konten database: Project (judul+deskripsi), SkillGroup (judul) + Skill-
  Subgroup (label), About (bio + judul+deskripsi tiap highlight). Field-nya
  disimpan dobel per bahasa (`titleEn`/`titleId`, dst — lihat poin 6). Yang
  TIDAK diterjemahkan: nama skill/tech itu sendiri (React, Laravel, dst —
  proper noun, sama di semua bahasa) dan seluruh teks statis Hero/Navbar/
  Footer/Contact (tetap dari translations.ts seperti biasa).
- Form admin (Project/SkillGroup/Highlight/Bio) sekarang punya 2 input
  berdampingan per field yang bisa diterjemahkan (English & Indonesia)
- Chatbot SUDAH terhubung ke Gemini, jawab berdasar data Projects/Skills/
  About dari database (pakai kolom *En sebagai referensi — modelnya sendiri
  yang menyesuaikan bahasa balasan ke bahasa visitor), dan menolak sopan
  pertanyaan di luar topik portfolio (instruksinya di src/lib/chatbot.ts)
- Field `tech`/`skills` di DB masih JSON string (peninggalan era SQLite),
  bukan native Postgres array — bisa disederhanakan kalau mau, tidak wajib
- Cuma 1 admin user (dari seed), tidak ada registrasi/role/lupa-password
- `prisma/seed.ts` pakai `createMany()` untuk Project/SkillGroup — TIDAK
  idempotent, jangan dijalankan ulang di DB yang sudah terisi


6. GOTCHA PENTING
====================
- **Prisma 7**: wajib driver adapter (`PrismaNeon`), connection string di
  `prisma.config.ts` (BUKAN di schema.prisma — field `url`/`directUrl` di
  blok `datasource` sudah tidak boleh ditulis sama sekali). Generator client
  custom (`prisma-client`) output ke `src/generated/prisma` (gitignored) —
  makanya `package.json` ada `"postinstall": "prisma generate"` biar Vercel
  regenerate otomatis saat `npm install`.
- **Next.js 16**: `middleware.ts` → `proxy.ts`, selalu jalan di Node.js
  runtime. Matcher-nya WAJIB exclude header `next-action`, kalau tidak
  Server Action di halaman admin bisa nge-logout paksa user (proxy ke-trigger
  ulang oleh POST balik Server Action itu sendiri). `requireAdmin()` tetap
  dipasang di tiap Server Action sebagai lapis kedua, jangan andalkan proxy
  saja.
- **Tailwind v4**: gradient utility `bg-linear-to-*`/`bg-radial` (bukan
  `bg-gradient-to-*` v3). Custom `--animate-*` theme token tidak auto-
  generate `ease-*` utility. `animate-*` digabung arbitrary property
  `[animation-delay:...]` dalam satu `@apply` bisa salah compile — pakai
  inline `style={{ animationDelay }}` kalau butuh delay per-elemen.
- `FormEvent`/`FormEventHandler` dari `@types/react` versi ini deprecated —
  pakai `SubmitEvent<HTMLFormElement>`.
- `next/image` butuh `images.remotePatterns` di `next.config.ts` kalau
  sumber gambarnya remote host (mis. Vercel Blob) — tanpa ini akan reject.
- **Pola field 2 bahasa** (`titleEn`/`titleId`, dst): pilihan-nya kolom
  duplikat per field (bukan tabel terjemahan terpisah) — simpel buat skala
  project ini. Server component (About/Skills/Projects Section.tsx) TETAP
  fetch SEMUA kolom bahasa dari Prisma lalu oper keduanya ke client
  component (Grid/Content) — bahasa aktif ada di client-only state
  (`localStorage`), server TIDAK tahu bahasa mana yang aktif, jadi pemilihan
  field `*En` vs `*Id` HARUS terjadi di client component, bukan di server.
- `npx prisma migrate dev` (mode interaktif) GAGAL kalau dijalankan dari
  shell non-interactive (agent/CI) DAN skema-nya nambah kolom required ke
  tabel yang sudah ada isinya (Prisma minta konfirmasi cara handle data
  lama). Solusinya: bikin folder migrasi manual di
  `prisma/migrations/<timestamp>_<nama>/migration.sql` isi SQL sendiri
  (ADD COLUMN nullable → UPDATE backfill dari kolom lama → SET NOT NULL →
  DROP kolom lama), lalu `npx prisma migrate deploy` (non-interactive,
  langsung apply + catat ke `_prisma_migrations`).
- **Turbopack dev cache kadang basi**: perubahan CSS/komponen tidak ke-
  reflect walau dev server sudah di-restart. Fix: `rm -rf .next` lalu
  `npm run dev` lagi.
- Kalau start dev server berkali-kali di background tanpa mastiin proses
  lama mati, port 3000 bisa "nyangkut" ke proses basi (Next auto-pindah ke
  3001 tapi tidak selalu ke-notice). Cek `fuser 3000/tcp` buat cari PID
  persis by port — `pkill` by nama proses kadang tidak match karena nama
  proses di `ps`/`ss` beda dari yang tercatat di `/proc/*/cmdline`.


7. DEPLOY KE VERCEL
======================
- Sudah live: repo GitHub `themeeps/port_next`, project Vercel `port-next`.
- SQLite TIDAK akan jalan di Vercel (filesystem serverless read-only) —
  makanya database sudah pindah ke Neon Postgres dari awal.
- Env var di Vercel dashboard (Settings → Environment Variables) — isi SAMA
  PERSIS kayak `.env` + `.env.local` lokal, TIDAK otomatis ke-push karena
  gitignored: `DATABASE_URL`, `DIRECT_URL`, `RESEND_API_KEY`, `AUTH_SECRET`,
  `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `BLOB_READ_WRITE_TOKEN`, `GEMINI_API_KEY`.
  Setelah nambah/ubah env var, WAJIB redeploy — Vercel tidak auto-apply ke
  deployment yang sudah jalan.
- Kalau nambah env var baru: tetap harus di-push lewat git dulu (commit
  kode yang makai env var itu), BARU isi value-nya di Vercel dashboard,
  BARU redeploy.
